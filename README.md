# Proxmox Ubuntu Server 26.04 Autoinstall profiles

**Destructive:** the MySQL profiles wipe two virtual disks; the single-disk profiles wipe `/dev/sda`. Always validate on a disposable VM before production.

## Profiles

| Directory | Firmware | Installed IPv6 | Disk layout |
|---|---|---|---|
| `profiles/uefi/mysql-2disk/` | OVMF/UEFI | enabled/default | 32G OS + 48G MySQL |
| `profiles/uefi/mysql-2disk-noipv6/` | OVMF/UEFI | disabled | 32G OS + 48G MySQL |
| `profiles/bios/mysql-2disk/` | SeaBIOS/BIOS | enabled/default | 32G OS + 48G MySQL |
| `profiles/bios/mysql-2disk-noipv6/` | SeaBIOS/BIOS | disabled | 32G OS + 48G MySQL |
| `profiles/uefi/single-disk/` | OVMF/UEFI | enabled/default | `/dev/sda`, EFI and root partitions |
| `profiles/bios/single-disk/` | SeaBIOS/BIOS | enabled/default | `/dev/sda`, BIOS boot and root partitions |
| `profiles/uefi/single-disk-noipv6/` | OVMF/UEFI | disabled | `/dev/sda`, EFI and root partitions |
| `profiles/bios/single-disk-noipv6/` | SeaBIOS/BIOS | disabled | `/dev/sda`, BIOS boot and root partitions |

The `profiles/bios/` and `profiles/uefi/` directories each contain the available profiles. Each profile directory contains `user-data` (`#cloud-config`) and `meta-data` for the Cloud-init NoCloud web datasource. Pass the profile name (`mysql-2disk`, `mysql-2disk-noipv6`, `single-disk`, or `single-disk-noipv6`) to the seed script; it selects the firmware directory automatically. Do not rename the seed files to `.yaml` on the public URL. A single `autoinstall.yaml` URL by itself is not a NoCloud seed directory.

All profiles use the `en_US.UTF-8` locale and US keyboard layout, select the Ubuntu Server minimal installation source, configure no proxy, and request no additional snaps. The minimal image may itself include snaps; the profiles do not remove them. The source ID depends on the ISO: confirm `ubuntu-server-minimal` appears in its `casper/install-sources.yaml` before installation. The published profiles prompt for network and identity settings, and OpenSSH Server is selected for installation. The script's static network mode supplies the network settings automatically while retaining the identity prompt.

The single-disk profiles have the same non-storage settings as the corresponding MySQL profiles with the same IPv6 choice. They use GPT and a single ext4 root filesystem occupying the remaining space after the firmware boot partition. They do not create LVM volumes or MySQL mounts. Confirm the intended disk is `/dev/sda` in the installer; other device types may use a different name. The MySQL profiles disable the autogenerated swapfile and use an LVM swap volume; the single-disk profiles leave swapfile creation to the installer default.

## Setup

1. Publish this directory tree in a **public GitHub repository**, preferably pinning a known Git commit/tag instead of referencing a moving branch (`main`) for production installations.
2. Prepare a fresh Proxmox VM with the Ubuntu Server ISO as a CD-ROM. For a MySQL profile, attach **only two target disks** of 32 GiB and 48 GiB. For a single-disk profile, attach one target disk that appears as `/dev/sda`. Select either `OVMF` (UEFI) or `SeaBIOS` (BIOS). Use DHCP for the web-hosted seed below, or use [static networking with a local seed ISO](#static-networking-with-a-local-seed-iso).
3. On the Proxmox host, set the cloud-init URL in the VM's SMBIOS serial (replace the sample repo with yours):

   ```bash
   ./set-proxmox-seed.sh 120 pavelsg/ubuntu-autoinstall single-disk main
   qm start 120
   ```

   The script reads the VM configuration: `bios: ovmf` selects `uefi`, while `bios: seabios` or an omitted `bios` setting selects `bios`. It does not change the VM firmware. Use `mysql-2disk` or `mysql-2disk-noipv6` for a MySQL layout. Replace the repository if using a fork; omit `main` to default to `main`.

   The script preserves the existing SMBIOS UUID and other fields while adding the seed URL as the system serial. An existing NoCloud serial can be updated by rerunning the script. If the serial serves another purpose, the script stops so you can merge it manually. Alternatively, edit the ISO GRUB `linux` command line to include:

   ```text
   autoinstall ds=nocloud\;s=https://raw.githubusercontent.com/pavelsg/ubuntu-autoinstall/main/profiles/uefi/mysql-2disk-noipv6/
   ```

   GRUB must escape the semicolon (`\;`). When setting the URL manually, use `profiles/bios/PROFILE/` or `profiles/uefi/PROFILE/` for the VM's firmware and retain the trailing `/`; do not link directly to `user-data`.

4. At the Ubuntu installer: provide **network settings** (`DHCP` or `Manual IPv4` with subnet, IP, gateway, DNS) and **identity** (hostname, username, password). Storage partitioning is not presented for editing. Disk wipe confirmation may still appear if `autoinstall` is not on the installer kernel command line.
5. After installation, remove or deprioritize the ISO and reboot. Verify `lsblk`, `sudo lvs`, `ip -4 addr`, `ip route`, `resolvectl status`, and for no-IPv6 variants `cat /proc/sys/net/ipv6/conf/all/disable_ipv6`.

## Static networking with a local seed ISO

The web-hosted seed is fetched **before** the installer network configuration screen, so the VM normally needs DHCP and access to GitHub first. Supply `--ip` and `--gateway` to have the Proxmox host download the profile and build a local NoCloud seed ISO instead. The VM can then read its installation and network settings without DHCP or access to GitHub. The host needs Internet access, and the VM still needs connectivity for installation updates and packages.

Keep `prepare_local_seed.pl` alongside `set-proxmox-seed.sh`; using a checkout of the repository is the simplest way to provide both files. Static mode uses Perl with `YAML::XS` (0.84 or later), `NetAddr::IP`, and `JSON::PP`, available with Proxmox VE 8 and later. It does not require Python or PyYAML. Ensure the host has the download and ISO tools:

```bash
apt install curl genisoimage
```

With the VM stopped, run:

```bash
bash ./set-proxmox-seed.sh 103 pavelsg/ubuntu-autoinstall single-disk-noipv6 main \
  --ip 10.0.0.34/24 --gateway 10.0.0.1
qm start 103
```

DNS defaults to the gateway (`10.0.0.1` in this example). The gateway must provide DNS resolution; otherwise supply a resolver explicitly, such as `--dns 1.1.1.1`.

| Option | Meaning | Default |
|---|---|---|
| `--ip` | Static IPv4 address with CIDR prefix, such as `10.0.0.34/24` | Required for static mode |
| `--gateway` | IPv4 default gateway | Required with `--ip` |
| `--dns` | IPv4 DNS resolver | Gateway address |
| `--interface` | Proxmox NIC to configure; matched in the guest by its MAC address | `net0` |
| `--storage` | Proxmox storage enabled for ISO content | `local` |
| `--seed-slot` | CD-ROM device for the seed, such as `ide3` | Automatically select a free IDE slot, or reuse this script's existing seed slot |

The script detects BIOS or UEFI, downloads the selected profile, and modifies a temporary per-VM copy. The seed ISO contains `user-data`, `meta-data`, and `network-config`. The same static network configuration is supplied to the live installer and the installed system; only the identity screen remains interactive. The repository's profile files are not modified.

The seed ISO is attached as an additional CD-ROM, preserving the Ubuntu installer ISO and other devices. The script preserves the SMBIOS UUID and other fields and sets the NoCloud serial to `ds=nocloud`, replacing any previous web seed URL. Each run produces a new ISO on the selected storage. Reruns reuse the script's seed slot; older generated ISO files remain on storage until you remove them.

After installation, detach the generated seed CD-ROM along with the installer media. To return to web-hosted seed mode, detach the script's seed CD-ROM before rerunning without static network arguments; the script refuses web mode while its local seed remains attached.

## Disable IPv6

Use `single-disk-noipv6` or `mysql-2disk-noipv6` to disable IPv6. These profiles write `/etc/sysctl.d/99-disable-ipv6.conf` **in the installed system**, setting `net.ipv6.conf.all.disable_ipv6=1` and `net.ipv6.conf.default.disable_ipv6=1`. This takes effect after reboot. The live install environment can still use IPv6; this is intentional because the seed is fetched first. To disable only *automatic IPv6 addressing*, not the IPv6 stack, consider Netplan `dhcp6: false`, `accept-ra: false`, `link-local: []` in a noninteractive `network` definition instead.

## Custom static network configuration

The CLI's static mode generates this configuration automatically. For a manually customized profile, remove `network` from `interactive-sections` and add a Netplan-style `autoinstall.network` section. For example (adapt interface name/MAC and addresses):

```yaml
network:
  version: 2
  ethernets:
    ens18:
      dhcp4: false
      dhcp6: false
      accept-ra: false
      link-local: []
      addresses: [192.0.2.10/24]
      routes:
        - to: default
          via: 192.0.2.1
      nameservers:
        addresses: [1.1.1.1, 9.9.9.9]
```

This sample shows the `network` contents nested under `autoinstall:`, and requires per-VM adaptation. It does *not* solve the early network connectivity needed to fetch a web profile, so local NoCloud ISO or separate early-boot networking may still be needed.

## Add more profiles

Create a directory with the same profile name under both `profiles/bios/` and `profiles/uefi/`, copying an existing profile from the corresponding firmware directory. Change `storage.config` in each flavor for its boot layout, and give each flavor a unique `meta-data` instance ID. For reusable templates with same-size disks, don't use `size: smallest` / `largest`: set Proxmox virtual-disk serials and match by `serial:` instead. Each profile directory must contain both `user-data` and `meta-data`.

* For UEFI, create a FAT32 EFI System Partition at `/boot/efi` (example uses 1 GiB).
* For BIOS with GPT, create a 1 MiB `bios_grub` partition.
* `lv_tmp` uses the rest of the MySQL VG due to LVM metadata overhead, approximately 4 GiB rather than precisely 4 GiB.
* MySQL requires separate application configuration to use these directories; mounts alone do not configure MySQL.

## Validation

Run the tests with Ruby. Local seed tests also require the same Perl modules as the helper; on a Debian development machine these are provided by `libyaml-libyaml-perl`, `libnetaddr-ip-perl`, and Perl's core `JSON::PP` module. The CLI tests mock Proxmox and network access:

```bash
ruby tests/profile_settings_test.rb
ruby tests/seed_script_test.rb
ruby tests/local_seed_config_test.rb
ruby tests/local_seed_cli_test.rb
```

The profiles have **not** been installed in a real VM. Validate with the [official Subiquity validation script](https://canonical-subiquity.readthedocs-hosted.com/en/latest/howto/autoinstall-validation.html) and then test in a disposable Proxmox VM.
